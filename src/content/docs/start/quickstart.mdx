## Parse and read

Pick a language. The tab selection is shared across the site, so the rest of these pages
follow it.

<Tabs syncKey="implementation">
<TabItem label="TypeScript">

```ts
import { parse } from '@o3co/ts.hocon'

const cfg = parse(`
  server {
    host = "localhost"
    port = 8080
  }
`)

cfg.getString('server.host')   // "localhost"
cfg.getNumber('server.port')   // 8080
cfg.has('server.host')         // true
```

</TabItem>
<TabItem label="Go">

```go
import "github.com/o3co/go.hocon"

cfg, err := hocon.ParseString(`
  server {
    host = "localhost"
    port = 8080
  }
`)
if err != nil {
    log.Fatal(err)
}

host := cfg.GetString("server.host")  // "localhost"
port := cfg.GetInt("server.port")     // 8080
```

</TabItem>
<TabItem label="Rust">

```rust
use hocon;

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let config = hocon::parse(r#"
        server {
            host = "localhost"
            port = 8080
        }
    "#)?;

    let host = config.get_string("server.host")?;
    let port = config.get_i64("server.port")?;

    println!("Server: {}:{}", host, port);
    Ok(())
}
```

</TabItem>
<TabItem label="Python">

```python
import hocon

cfg = hocon.parse("""
    server {
        host = "localhost"
        port = 8080
    }
""")

cfg.get_string("server.host")   # "localhost"
cfg.get_int("server.port")      # 8080
cfg.has("server.host")          # True
```

</TabItem>
</Tabs>

The accessor names follow each language's conventions rather than a single cross-language
spelling — `getString` in TypeScript, `GetString` in Go, `get_string` in Rust and Python. What
they do is identical.

## Layer environment overrides

The pattern most configuration reaches for: a default in the file, overridden by the
environment when set, with nothing to change in code.

```hocon title="app.conf"
app {
  log-level = info
  log-level = ${?LOG_LEVEL}

  database {
    url = "postgres://localhost/dev"
    url = ${?DATABASE_URL}
    pool-size = 10
    pool-size = ${?DB_POOL_SIZE}
  }
}
```

`${?VAR}` resolves against the environment, and when the variable is unset the line is skipped
entirely — so the default above it survives. No templating step, no `envsubst`, no sentinel
values.
